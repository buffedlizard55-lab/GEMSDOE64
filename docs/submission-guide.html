Submission guide

Download, validate, submit — in that order.

This page exists so that nobody has to guess which file is which, or whether a file is cleared.

2. Verify before you submit

  1. Hash the file.

    sha256sum gems64-lane-ampsnr-37654-20261011.tif must match the receipt.

  2. Check the grid and the range.

    EPSG:32611, 100 m, 3730×3292, transform (100, 0, 243350, 0, −100, 4508550). Every value inside the footprint finite and in [0,1]; the writer refuses to emit anything else and never clips silently.

  3. Run the local validator.

    .venv/bin/python scripts/validate_submission.py FILE.tif. A local pass is necessary, never sufficient.

  4. Check the catalogue distance.

    Every dot must be at least 3 px (300 m) from the mapped catalogue; the emitted file satisfies this by construction and the receipt records the minimum.

3. Submit as an authorized operator

  1. Confirm the weekly cap yourself on the authenticated DrivenData page. This repository has never observed a cap value and never spends a slot.
  2. Upload the TIFF (or the ZIP) on the competition's “New submission” page and paste the recorded name and note if the portal asks for them.
  3. Keep the receipt.

    Only the submission-page receipt can support an ORGANIZER-CONFIRMED number. Copy it into evidence/organizer_receipt.json if it exists; until then every score in this repository is a labelled instrument.

  4. If the portal rejects the file, stop and record the full error text verbatim. Do not “fix” it by guessing at nodata handling.

4. What would make a future candidate worth a slot

The lane's frozen gates are in PREREGISTRATION.md: beat the terrain-matched control by more than 2 paired SEs inside the interior stratum, keep instrument 2 within noise of its controls, clear the byte/pixel uniqueness check, and record the dot-pattern overlap honestly even when the literal clause is unsatisfiable.
