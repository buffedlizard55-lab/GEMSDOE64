What the metric rewards—and what it does not prove

The challenge evaluates predicted faults against new expert labels. A promising emission rule is not a validated geological discovery, and a public score is not a private-round result.

Official target and metric

The official problem description states that known public fault labels are incomplete and that the initial prize test contains newly identified expert-labeled faults. The task is fault prediction throughout the GeoDAWN region, not direct prediction of geothermal vents or temperature.

For this competition, the distance-weighted Tversky index uses alpha = 0.2, beta = 0.8, and a triangular distance kernel with R = 300 m. In the official definition, a prediction receives distance-dependent credit near a truth pixel; false-positive and false-negative contributions are also distance weighted. In compact form:

DTI = TPw / (TPw + 0.2 × FPw + 0.8 × FNw + epsilon)

This makes recall important, but does not make arbitrary dense predictions safe. A long line far from the new labels can add false-positive mass; nearby predictions can receive partial credit; and neighboring predictions compete for overlapping coverage. The exact per-pixel gain therefore depends on the local truth draw, kernel, and all existing picks.

The alpha-times-optimal-score rule: derivation and scope

For a simple unweighted binary selection set A, independent calibrated per-pixel probabilities qᵢ, and alpha + beta = 1, let T = Σ(i∈A) qᵢ and P = Σ(all i) qᵢ. The ratio of expected confusion counts is:

Splug-in(A) = T / (alpha·|A| + beta·P).

Adding one unweighted hard prediction with calibrated probability q changes the numerator to T + q and denominator to D + alpha. The ratio improves exactly when q > alpha·Splug-in(A). This is the algebraic version of the familiar calibrated F1 threshold result; the cited Lipton–Elkan–Narayanaswamy paper is linked in the source register. As a purely illustrative plug-in calculation, if Splug-in = 0.30, then alpha·S = 0.06. That cutoff is a theoretical quantity, not a HOLDOUT-DTI, not an ORGANIZER-CONFIRMED score, and not an observed competition result.

Scope correction: that derivation compares ratios of expected counts. It does not establish the same cutoff as a universal rule for the mean of per-raster ratios, especially with a spatial max/triangular kernel. In general, E[TP / denominator] is not E[TP] / E[denominator]. We tested that distinction before designing a placement algorithm.

Reproducible synthetic counterexample — not a competition score

The standard-library script scripts/synthetic_expected_dti_check.py enumerates all 32 binary truth maps for a synthetic one-row, five-cell raster with calibrated probabilities [0.90, 0.60, 0.20, 0.08, 0.05]. It calculates two distinct objectives; it has no 300 m kernel and uses no competition labels.

  • SYNTHETIC mean-per-map utility only: the globally optimal selected set contains the first two cells, with mean unweighted DTI utility 0.7972702684.
  • SYNTHETIC candidate test only: the third cell has probability 0.20, above alpha × exact-mean optimum = 0.1594540537, yet adding it changes the mean per-map utility by −0.0048653377.
  • SYNTHETIC ratio-of-expected-counts only: the same third cell improves the plug-in objective by +0.0189223808, and the plug-in optimum includes it.

These are mathematical toy utilities, not HOLDOUT-DTI, not ORGANIZER-CONFIRMED, and not competition scores. The test verifies that the shortcut can be correct for the plug-in objective while failing for finite-ensemble mean DTI. The full competition kernel may further change each marginal gain.

Implementation decision: do not independently threshold pixels at alpha × S*. Use it, at most, as an algebraic diagnostic. Actual acceptance/pruning must use the exact evaluator's mean marginal DTI gain across the required uncertainty realizations.

Why a dotted candidate could outperform a dense field (plausible, not established)

The prior GEMSDOE pages supplied in the prompt describe several sparsified, dotted, spacing, and max-coverage experiments. A scientifically plausible mechanism is that a sparse arrangement removes redundant predicted mass while retaining predictions close enough to truth to receive triangular-kernel credit. In metric terms, this could reduce weighted false-positive contribution without losing as much weighted true-positive coverage. It is not possible to infer causality from the final public value alone: different masks, pixel budgets, label distributions, and submission dates can all change results.

There is a source inconsistency that prevents a stronger claim: the GEMSDOE32 owner site describes its H33-2-B2 artifact as a candidate formed by pruning a prior sparse/dotted map around known catalogue traces, and explicitly states that the artifact has no organizer score; the prompt describes an H33 entry as scored. Its own documentation separates proxy/Monte-Carlo analyses and model projections from organizer scores. Sparse pruning is a plausible mechanism for reducing redundant false-positive mass while retaining kernel-near credit, but neither the precise submitted file nor the cause of the reported result is established. Without a DrivenData submission-page receipt and the exact submitted file hash, the attribution cannot be resolved. This site does not copy that artifact.

The public leaderboard is live and has moved since the snapshot quoted in the prompt. It is not the private holdout or an organizer receipt. No promise that this project can beat any particular public result is made.

What the proposed holdout can validate

With the shared tools and authorized data, whole segments of visible catalogue faults can be hidden with a spatial buffer. Catalogue-based features must be rebuilt only from visible traces, and visible traces must be masked pixel-exactly. Pool the held-out truth and predictions through the competition evaluator, then report the evaluator version, withheld-positive count, and a 95% block-bootstrap confidence interval.

This is a hide-and-recover proxy. It measures whether the pipeline recovers spatially withheld examples from the known catalogue; it cannot directly show performance on genuinely new faults that were never in the catalogue. The holdout is a promotion gate, not a guarantee of leaderboard rank.

Before trusting a feature, run the specified single-feature canary. An unusually high AUC (>0.90 under the requested protocol) is a leakage alarm, not an achievement, until its provenance is explained.

Current scientific conclusion

The expected-DTI placement method is a reasonable, metric-aligned hypothesis, but it is not validated on this checkout. There is no spatial holdout result, confidence interval, leakage test, ensemble/TTA/MC-dropout surface, registry comparison, exact scorer run, written raster, or validator output. The only verified experiment is the synthetic threshold-scope check above. The verdict remains negative and no submission file is offered.
