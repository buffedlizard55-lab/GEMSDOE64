Executive summary / Submission guide

Can I download and submit?

Not from this run. No TIFF is cleared or offered. The negative verdict is the deliverable.

No bypass: a valid GeoTIFF format, unique filename, or different file hash does not prove a valid new submission. The performance and registry gates must also pass.

Why this run stopped

The shared registry rule treats every positive finite prediction as a dot and measures the fraction within three pixels of prior dots. One prior's three-pixel neighborhood covers the entire allowed off-catalogue domain, so every nonempty candidate has 100% forward overlap against a 70% limit. A different interpretation requires an explicit protocol change, not a private exception.

The exact shared feature cache and buffered out-of-fold model predictions are also unavailable. No geological holdout was run; no DTI, confidence interval or score improvement is claimed.

The submission process—once a future run passes

  1. Read the verdict before downloading.

    The page must say an artifact passed the promotion gate and identify its immutable SHA-256. A negative or incomplete run has no TIFF download. This site is a static evidence viewer, not a browser training service.

  2. Verify holdout and uniqueness receipts.

    Require the evaluator version, withheld positive count, 95% interval, and gains exceeding two paired block-bootstrap SEs against spacing/MCLP on the same surface, plus a comparable historical best. Surface and final-dot registry checks and full hash/pixel comparisons must pass.

  3. Download the new single-band GeoTIFF.

    Use only the newly generated cleared file—not a reference, sample, prior raster or synthetic fixture. It must be float32, EPSG:32611, 100 m, shape 3730 × 3292, affine (100, 0, 243350, 0, −100, 4508550). All footprint values must be finite and in [0,1]. The shared export uses zero outside, no nodata sentinel, and no hidden interior mask.

  4. Check the exact serialized file.

    Run python scripts/validate_submission.py FILE.tif. If using a ZIP, it must contain exactly that one TIFF. The writer's name and note are limited to 140 characters. Local validation is not organizer acceptance.

  5. Use the separate slot selector.

    Confirm the actual weekly cap on the authenticated submission page and obtain slot authorization. Neither this site nor this run spends a slot. No weekly-cap value has been observed here.

  6. Submit and retain the organizer receipt.

    On DrivenData's “New submission” page choose the cleared file, paste its unique name/note where supported, and submit only after authorization. Archive the file hash and submission-page receipt. Only that receipt can support an ORGANIZER-CONFIRMED result.
