Executive summary

How to put a prediction into the competition — and what is standing in the way

1. Submission mechanics (from the competition's own pages)

  1. Sign in to DrivenData and open the GEMS competition page, then the Submit tab (competition home, problem description).
  2. Choose a file: a single-band GeoTIFF (.tif) or a .zip containing exactly one GeoTIFF.
  3. The raster must match the submission template's CRS, shape and geotransform. For this competition that is EPSG:32611 (UTM 11N), 3730 rows × 3292 columns, 100 m pixels, origin (243350, 4508550), north-up.
  4. Values must be in [0, 1]. The portal rejects anything else with “Predicted values must be in range [0, 1]” — the error this project hit earlier with a file whose values were outside that range.
  5. Give the submission a unique name and a note of at most 140 characters.
  6. Every accepted upload consumes one weekly submission slot; the private-test score is not shown on the public leaderboard.

Why the red banner, in one sentence: the literal registry rule cannot be satisfied by any non-empty candidate while five saturating priors sit in the checked inventory, and that saturatation is measured with matched random controls rather than assumed (calib_r13lattice_00904.tif, r11_greedy_mp.tif, r13_lattice_s5_00904.tif, r14_union_tips10_lat6.tif, witness_17_E-proba-multiscale.tif). The portal will accept this file — the local preflight reproduces the portal's documented requirements and passes. Whether you should spend a slot is a scientific judgement and a forecast we refuse to invent: the surrogate holdout number below is a hide-and-recover measurement, not a leaderboard estimate.

3. What still blocks a confident submission

  1. No organizer-issued truth. The hidden evaluation labels are not published; every number in this repository is either a surrogate holdout measurement or an owner-reported score.
  2. The registry is dense. The literal registry gate compares the candidate's positive support with every prior's support at a 3 px radius; at least one indexed prior carries positive mass almost everywhere, so the literal forward-overlap statistic saturates near 1.0 for any non-empty candidate. That is a property of the rule meeting a dense prior, not proof of copying — and it is reported, not exempted.
  3. Native-resolution lidar is not reachable from this sandbox. The lane's 1 m processing path is implemented and unit-tested, but the tile hosts are outside the sandbox's allowed egress; see irregularities.
